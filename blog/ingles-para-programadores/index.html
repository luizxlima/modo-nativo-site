Inglês para programadores: vocabulário de daily, deploy e PR

1 de novembro de 2026 5 min de leitura Por Equipe Modo Nativo

O inglês para programadores tem uma ironia: você lê documentação, nomeia variáveis e escreve commits em inglês todo dia, mas trava na primeira daily com um time gringo. O problema não é vocabulário técnico, que você já tem. É a fala: a frase que precisa sair em dois segundos quando o scrum master pergunta "Any blockers?". Este artigo organiza o que você realmente fala no dia a dia de um time internacional e mostra como treinar isso.

Daily scrum: as três perguntas e como respondê-las

A daily segue quase sempre o mesmo roteiro: o que você fez ontem, o que vai fazer hoje e se tem algum bloqueio. Como o formato é fixo, dá para automatizar as frases.

Ontem (passado simples):

  • "Yesterday I finished the login endpoint and opened a PR." (Ontem terminei o endpoint de login e abri um PR.)

  • "I spent most of the day debugging the payment flow." (Passei a maior parte do dia debugando o fluxo de pagamento.)

Hoje (going to ou will):

  • "Today I'm going to address the review comments and start on the tests." (Hoje vou atender os comentários da revisão e começar os testes.)

  • "I'll pair with Ana on the migration." (Vou fazer pair programming com a Ana na migração.)

Bloqueios:

  • "No blockers." (Sem bloqueios.)

  • "I'm blocked on the API key. I'm waiting on DevOps." (Estou travado na chave da API. Estou esperando o DevOps.)

  • "I need someone to review my PR before I can move on." (Preciso que alguém revise meu PR antes de seguir.)

Vocabulário de código e versionamento

Muita coisa você já conhece lendo, mas a pronúncia na fala é outra história. Palavras que brasileiros costumam falar errado:

  • deploy: /di-PLÓI/, com a sílaba forte no final. "We deployed to staging this morning." (Fizemos deploy em staging hoje de manhã.)

  • merge: /mãrdj/, uma sílaba só. "Can you merge my branch?" (Você pode mergear minha branch?)

  • cache: /késh/, igual a "cash". Não é "cá-che".

  • query: /KUÍ-ri/. "The query is timing out." (A query está estourando o tempo.)

  • variable: /VÉ-ri-a-bol/, sílaba forte na primeira.

  • schedule: /SKÉ-djul/ (americano) ou /CHÉ-djul/ (britânico).

Frases comuns no fluxo de PR:

  • "I opened a pull request for the feature." (Abri um pull request para a feature.)

  • "Could you take a look at my PR when you get a chance?" (Você poderia dar uma olhada no meu PR quando puder?)

  • "I left a few comments. Nothing major, just naming." (Deixei alguns comentários. Nada grave, só nomenclatura.)

  • "Looks good to me." (Está bom para mim.) Nos comentários aparece como LGTM.

  • "I'll rebase and push again." (Vou fazer rebase e subir de novo.)

Bugs, incidentes e code review

Relatar um bug em inglês segue um padrão: o que acontece, o que deveria acontecer e como reproduzir.

  • "The form crashes when the user submits an empty field." (O formulário quebra quando o usuário envia um campo vazio.)

  • "It should show a validation error instead." (Deveria mostrar um erro de validação.)

  • "Steps to reproduce: go to checkout, leave the email blank and click Pay." (Passos para reproduzir: vá para o checkout, deixe o e-mail em branco e clique em Pagar.)

  • "I can't reproduce it locally." (Não consigo reproduzir localmente.)

  • "It's a race condition." (É uma condição de corrida.)

  • "We need a hotfix in production." (Precisamos de um hotfix em produção.)

Para dar feedback em code review sem soar rude:

  • "What do you think about extracting this into a helper?" (O que você acha de extrair isso para um helper?)

  • "Minor: this could be a const." (Detalhe: isso poderia ser uma const.)

  • "Nit: trailing space here." (Picuinha: espaço sobrando aqui.)

O "nit" (de nitpick) é uma convenção de times gringos para sinalizar que o comentário é pequeno e opcional.

Reuniões de planejamento e estimativas

  • "How many story points would you give this?" (Quantos story points você daria para isso?)

  • "I'd say it's a three. The backend is straightforward, but the UI has edge cases." (Eu diria que é um três. O backend é direto, mas a UI tem casos de borda.)

  • "Can we break this ticket down?" (Podemos quebrar essa tarefa?)

  • "That's out of scope for this sprint." (Isso está fora do escopo desta sprint.)

  • "Let's push it to the backlog." (Vamos jogar para o backlog.)

Por que programador trava ao falar e como resolver

Quem programa passa o dia lendo e escrevendo inglês, então o cérebro está acostumado a processar o idioma com calma, no próprio ritmo. A fala tira esse controle: o colega de Berlim fala rápido, emenda palavras e espera resposta na hora. O ouvido não foi treinado para esse ritmo e a boca nunca praticou as frases.

A solução é treinar exatamente as frases da daily e do code review em voz alta, por cima do áudio de um nativo, até elas saírem sem pensar. É o mesmo princípio de decorar atalhos do editor: no começo você pensa, depois a mão vai sozinha.

Conclusão: inglês para programadores é treino de fala, não de leitura

O inglês para programadores que destrava vagas remotas em dólar não está na documentação, está na daily, no PR e no incidente de sexta à noite. As frases são poucas e repetitivas, o que é ótimo: dá para automatizar em semanas.
